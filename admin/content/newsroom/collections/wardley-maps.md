None of these articles is about Wardley maps. Each one reaches for the same move at the point where its argument needs it: place the thing on the evolution axis, genesis, custom-built, product, commodity, and read the consequence off where it sits. Read together, they show the map doing four different jobs.

- **As a drawing with its source.** [The Mandate Stack](/articles/the-mandate-stack.html) draws two maps of one agent team, one from a person outside it and one from inside, and publishes the source next to each render so the placements can be argued with.
- **As a rule for how much care a change gets.** [If somebody built a company on code review](/articles/if-somebody-built-a-company-on-code-review.html) answers a reader's questions about depth and cost with where the changed thing sits: explorers, villagers and town planners review differently.
- **As a life cycle for interfaces.** [Custom UIs are not the exception](/articles/custom-uis-are-not-the-exception.html): the first interface for a thing is genesis, the fifth is a product with a name.
- **As a life cycle for a body of writing.** [How much of this did I write?](/articles/how-much-of-this-did-i-write.html) places twenty years of posts, books and talks on the same axis, and finds the agent is fast because the record has commoditised.
- **As inertia.** [The SaaS apocalypse](/articles/saas-apocalypse-decided-by-inertia-not-by-ai.html) and [the deck I could not download](/articles/the-deck-i-could-not-download.html) both turn on Wardley's climatic pattern that past success breeds inertia, applied once to software incumbents and once to a twenty-year-old service.

The maps themselves live at [wardley-maps.sgit.ai](https://wardley-maps.sgit.ai/), whose thesis these articles share: a map is a claim, not a picture.
