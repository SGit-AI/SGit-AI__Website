# A proposed partnership between sgit.ai and Anthropic

**This site is already a Claude Code project, and vaults are how its sessions work together.** sgit.ai, its briefs, its deployment docs and most of its thirty-five published vaults are built and published by Claude Code sessions that share state through a vault. We would like to turn that working practice into a partnership: a vault connector in Anthropic's Connectors Directory, skills that teach Claude to use vaults well, and a place in the Claude Partner Network.

**Nothing on this page is confidential, and there has been no conversation yet.** Every statement about Anthropic comes from its own public pages, linked. Every statement about sgit points at the [deployment documentation](../deploy/index.md), a published vault or a page on this site. sgit is Apache-2.0, so Anthropic does not need our permission to run it or to build on it. A partnership is about doing that well and together. The general argument is on [the AI providers page](ai-providers.md).

## In short

- **The practice exists.** Claude Code sessions build this site and hand work to each other through vaults, and the deployment docs vault was written by two of them.
- **The connector has a home.** Claude's [MCP connector](https://platform.claude.com/docs/en/agents-and-tools/mcp-connector) reaches remote MCP servers from the API, Claude apps support custom remote connectors, and the [Connectors Directory](https://claude.com/docs/connectors/building/submission) takes remote MCP servers, MCP Apps and plugins.
- **Skills already exist.** [skills.sgit.ai](https://skills.sgit.ai/catalogue/index.html) publishes eight skills, three of them for working with vaults: using sgit, writing vault content, and building vault apps.
- **What we would like:** a place in the [Claude Partner Network](https://claude.com/partners), a review of the connector, and support through [Claude for Startups](https://claude.com/programs/startups).

## Where vaults fit Claude

| Meeting point | On Anthropic's platform | Status |
|---|---|---|
| **Agents read and write vaults** | Remote MCP servers via the API's MCP connector, custom connectors in Claude apps, and the Connectors Directory | Connector not built yet. Claude Code already works in vaults through the CLI. |
| **Vault apps call models** | Claude models, reached through the host bridge | Works today through OpenRouter. |
| **Vaults carry the work** | Claude Code output | This site and most of its vaults are exactly that. |
| **Skills** | Skills bundled in a plugin | Published on skills.sgit.ai; not in the directory. |

## Where we are with Anthropic today

Anthropic's tools are how this site is made, so this is the partnership closest to what we already do. There is no relationship beyond being a customer. RiskMandate.ai has published [agent behaviour policies](https://riskmandate.ai/agent-behaviour-policy.html) for Claude Code on the web and on the command line, Claude Desktop, and Claude with Gmail and Microsoft 365, and the risk side of this partnership will be written there.

## What a partnership could be

| Shape | What it would be | On their side |
|---|---|---|
| **1 · A vault connector** | A remote MCP server with read-only vault tools and one append tool, each tool titled and annotated as read-only or not, submitted to the Connectors Directory. | Directory review. |
| **2 · Skills in a plugin** | The vault skills from skills.sgit.ai bundled as a plugin, so Claude learns to commit, publish and hand over work as vaults. | Directory review. |
| **3 · A case study** | A site built and run by Claude Code sessions that share state through encrypted vaults, written up with its numbers. | The Claude Partner Network. |

## What we are asking Anthropic for

1. A place in the [Claude Partner Network](https://claude.com/partners).
2. A review of the vault connector and the skills plugin before submission to the Connectors Directory.
3. Support through [Claude for Startups](https://claude.com/programs/startups).
4. A conversation about the case study: a website and its vaults run by Claude Code sessions.

## What this page does not claim

- **No endorsement.** Anthropic has not endorsed sgit, and we have not spoken to anyone there about this. Product and programme descriptions quote Anthropic's own pages and documentation as of 24 September 2026.
- **The vault connector does not exist yet.** This page describes what it would be and which rules it would have to meet.
- **Being a heavy user is not a relationship.** It is the reason for this page.
